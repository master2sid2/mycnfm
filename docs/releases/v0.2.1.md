# mycnfm v0.2.1

*Released 2026-11-16 — patch release, and the first one published on GitHub.*

## Fixed

- **Files with secrets always end up private.** `~/.my.cnf`, the vault and
  `export` files used to be written through a fixed `<file>.tmp` name with a
  call that keeps the permissions of an existing file. A temporary file left
  behind with wider permissions (`0644`, say) could therefore make passwords
  readable by other users. Every write now goes through a randomly named
  temporary file whose mode is set to `0600` explicitly, synced to disk before
  it is renamed into place.
- **A line break in a value no longer splits it.** A newline in a password —
  or in any other quoted value — used to end the line in `~/.my.cnf`, so the
  rest of the value became an option line of its own. It is now written as
  `\n` inside the quotes, which MySQL and MariaDB read back as the original
  character (checked with `my_print_defaults` on MySQL 8.0 and 8.4).
- **Socket paths with spaces work**: they are quoted like other values.
- **A damaged vault file is reported, not crashed on.** A nonce length other
  than 12 in the file used to make `mycnfm` panic.

## Changed

- **The first run asks for the new master password twice**, and creates no
  vault if the two entries differ. A typo used to lock the new vault for good.

## Also in this release

- Releases are built on GitHub: binaries for Linux and macOS (amd64 and
  arm64) with `SHA256SUMS`, and `go install github.com/master2sid2/mycnfm@latest`
  works.
- Updated `golang.org/x/crypto` and the other `golang.org/x` modules.

## Upgrade notes

None. Vaults and `~/.my.cnf` files from 0.2.0 work unchanged.
