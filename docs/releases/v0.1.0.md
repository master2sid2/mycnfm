# mycnfm v0.1.0

*Released 2026-09-16 — first release.*

`mycnfm` keeps your MySQL/MariaDB logins in one encrypted vault and writes the
one you pick into `~/.my.cnf`, so you never have to edit that file by hand or
keep old passwords in it.

## Highlights

- **Encrypted vault.** AES-256-GCM, key derived from your master password with Argon2id. The vault lives at `~/.config/mycnfm/vault.enc`.
- **A TUI built around how you think about servers.** Environments (`stage`, `prod`) that contain folders, groups and tags; search across an environment; a second view that pivots from *env → group* to *group → env*.
- **`enter` applies a profile.** `~/.my.cnf` is written atomically with mode `0600`, and passwords are always quoted and escaped, so special characters survive the option-file parser.
- **`x` (or `mycnfm clean`) wipes it again** — and clean needs no master password.

## What's in it

**Organising profiles**

- Environments and nested folders — create, rename, move, delete.
- Groups render as section headers inside a folder; `v` toggles between *by folder* and *by group*.
- Tags are coloured chips (the colour comes from the tag name, so it is stable).
- `/` searches the current environment recursively; `s` cycles the sort (name, group/env, updated), `S` reverses it.

**A profile** has a name, group, port, socket, user, password, database, tags and notes. Everything except the name is optional — you can keep just a user and a password. There is no `host` field on purpose: the same login often serves several servers, and the server is normally given on the command line, which overrides the option file.

**Options.** The catalog (`O`) defines key/value options once; every profile shows them as checkboxes. The vault is seeded with `default-character-set = utf8mb3`, off until you enable it on a profile. Per-profile *custom options* exist only on that profile.

**Output.** Port `3306` and blank fields are omitted. Only a non-default port is written.

**Maintenance.** `passwd` re-encrypts the vault under a new master password without plaintext ever touching disk. `export` and `import` round-trip a plaintext JSON copy — for rotating the password by hand, or handing a configuration to a colleague who re-encrypts it under their own password. Both ask before overwriting.

None — first release.

## Known limitations

- The first run creates the vault with whatever master password you type; there is no confirmation prompt. Change it with `mycnfm passwd`.
- Options are only written to `[client]` (per-section options arrive in 0.2.0).
- Nothing removes `~/.my.cnf` automatically — use `x` / `mycnfm clean` (an auto-wipe timer arrives in 0.2.0).
- Running two `mycnfm` instances at once is not supported: the last one to save wins.
