# mycnfm v0.2.0

*Released 2026-09-20.*

This release is about **hygiene and automation**: you type the master password
once per session, profiles can be applied from scripts, `~/.my.cnf` cleans
itself up, and options can finally target `[mysqldump]`.

## Highlights

### `~/.my.cnf` wipes itself after an hour

Every apply now schedules a wipe — **one hour by default**.

```bash
mycnfm -t 30m                       # TUI session: every profile applied in it, 30 minutes
mycnfm apply stage/auth-01 -t 15m   # one profile, 15 minutes
mycnfm apply stage/auth-01 -t off   # no timer (0 also disables)
```

A small detached copy of `mycnfm` does the wiping. It needs no password — its
arguments are just the file path, a hash and the deadline — and it wipes **only
if the file still contains exactly what was written**. If you have since picked
another profile or edited the file by hand, it leaves it alone. Only one timer
runs at a time: a new apply or a `clean` stops the previous one. The header
counts down (`● stage/auth-01 · wipes in 47m`).

If the timer process did not survive — a reboot, a logout that kills your
processes — the deadline is also stored in the vault, and the next `mycnfm`
run wipes an expired, untouched file.

### The master password is asked once per login session

After the first successful unlock, `mycnfm` keeps the *derived key* (never the
password) in the Linux kernel session keyring. The next run — TUI, `apply`,
`list`, `export` — opens the vault without asking. No daemon, no file, nothing
in the environment. Logging out forgets it, and so does the new
`mycnfm lock`. `passwd` deliberately ignores the cache and always asks.

### Apply from a script

```bash
mycnfm list                          # stage/auth-01, prod/billing-db, …
mycnfm apply stage/auth-01           # like pressing enter in the TUI
mycnfm apply auth-01                 # by name, if unique (otherwise it lists the candidates)
mycnfm apply stage/auth-01 -o -      # print the file instead; touches nothing on disk
```

For cron/CI, where there is no login session, set `MYCNFM_PASSWORD_FILE` (or
`MYCNFM_PASSWORD`). [docs/automation.md](../automation.md) covers how to set
these **without leaving the password in your shell history** (bash, zsh, fish,
POSIX sh).

### Options in `[mysqldump]` (and any other section)

`mysqldump` does not reliably honour `default-character-set` from `[client]`
across MySQL/MariaDB versions, so a setting that must apply to dumps needs to
live in `[mysqldump]`. Options now have a **Section** (blank = `client`), and
the file is written with one block per section:

```ini
[client]
user     = app
password = "s3 cret#"
default-character-set = utf8mb3

[mysqldump]
default-character-set = utf8mb4
```

The same option can exist in several sections with different values, enabled
independently per profile. Set the section in the options catalog (`O`) or in a
profile's *Custom options*. See [docs/options.md](../options.md).

### The header tells you when the file no longer matches

`mycnfm` remembers a hash of what it wrote. If `~/.my.cnf` is later edited,
deleted, or replaced, the header, the list row and the details panel show
`⚠ … — file changed` or `— file missing` instead of a false `● active`. A file
that was simply wiped (by the timer, or by `mycnfm clean` from a shell) is
recognised as such and just clears the active profile.

## Also new

- `make build-darwin` cross-compiles macOS binaries (`arm64` and `amd64`) into `dist/`.

## Upgrade notes

Please read the first two.

1. **Applying now schedules a wipe one hour later.** Previously a profile stayed in `~/.my.cnf` until you cleaned it. To keep that behaviour, pass `-t off`, or launch the TUI with `mycnfm -t off`.
2. **A cached unlock key is now created on first use** (Linux). If you would rather not have one, run `mycnfm lock` after each session, or set `MYCNFM_PASSWORD_FILE` instead. See [SECURITY.md](../../SECURITY.md).
3. **Vaults are forward-compatible, not backward-compatible.** A 0.1.x vault opens unchanged and gains a few optional fields (`active_hash`, `active_expires`, and `section` on options). If you use sections, do not open that vault with 0.1.x again — it ignores them and drops them on its next save. Back up `~/.config/mycnfm/vault.enc` before upgrading if you might roll back.
4. Renaming a catalog option onto an existing key is now refused. It used to overwrite the other option silently.

## Known limitations

- **Linux-only session cache.** On macOS the password is asked on every run. The background timer identifies its own process with `ps` there and has not been exercised on a Mac. Windows is not supported.
- **First-run password has no confirmation.** The vault is created with whatever you type at the first prompt; change it with `mycnfm passwd`.
- **Session keyring depends on your PAM setup.** With `pam_keyinit` (the norm on systemd distributions) each login gets its own keyring. Without it the kernel falls back to a per-user keyring that lives as long as any of your processes; `mycnfm lock` clears it either way.
- **Logout can kill the timer.** If your system kills user processes at logout, the timer dies with the session; the launch-time backstop then wipes the file at your next run. If you never run `mycnfm` again, the file stays.
- **An option key can appear once per section** — not twice within the same section.
- **No locking between instances.** Two `mycnfm` processes open at once can overwrite each other's changes; the last one to save wins.
- **Cosmetic:** in the profile form, a very long option label on the selected row can wrap onto a second line.
